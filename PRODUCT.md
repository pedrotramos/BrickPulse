# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Platform engineers investigate Databricks spend and turn evidence into prioritized changes. FinOps leaders need an executive overview of the same facts.

## Product Purpose

BrickPulse identifies opportunities to reduce Databricks spending, explains the evidence and effort, and estimates the effect of observed changes. It recommends actions; it does not execute resource changes.

## Operating Context

Authenticated Databricks App, Python/FastAPI backend, React frontend, reusable rules and daily precomputation. Installed per workspace as a Declarative Automation Bundle; account coverage is limited to the metastore region, and app access starts limited to the installing user.

## Capabilities and Constraints

Preserve all 42 rule definitions and current optional Apps/Genie surfaces. Financial estimates are not invoices or guaranteed savings. Data gaps must not appear as zero spend or no opportunities. Maintain scoped access and stable resource links. Translate the complete app into pt-BR, en and es; detect the browser language and persist explicit choices; unsupported languages fall back to English. Display USD without currency conversion.

## Brand Commitments

Name: BrickPulse. Approved plan: light analytical interface, graphite text, petrol interface accent, sidebar and global workspace selector. Approved logo: original option 3, Frequência, with five rounded vertical bars in orange #B94B2C. Preserve that exact original shape; the proposed eye/frequency fusion was rejected. The logo color is distinct from the unchanged petrol actions and selections. Implementation uses self-hosted Instrument Sans and JetBrains Mono because IBM Plex was unavailable offline; this substitution was disclosed during implementation. Technical depth with an executive summary. The user delegated execution of this direction and approved rebuilding the frontend.

## Evidence on Hand

The original rule engine, API and data contracts are present. Only the compiled original frontend was supplied; there are no editable frontend sources or original tests. Demonstration data must be visibly labeled.

## Product Principles

- Explain every financial figure with period, source, confidence and freshness.
- Keep calculations independent of language.
- Make the next useful action discoverable without concealing evidence.
- Preserve honest unknown and partial states.

## Accessibility & Inclusion

Keyboard operation, responsive layouts, WCAG AA contrast, localized dates/numbers/plurals, reduced motion.
